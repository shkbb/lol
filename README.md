# autopara — автоматичний вхід на пари ДУІКТ

Програма сама тягне розклад твоєї групи (за замовчуванням ТЦР-32) і заходить на пари
в Google Meet або Zoom у потрібний час. Мікрофон і камера вимкнені, звук теж.

Що вона робить:

- раз на годину бере розклад з [e-rozklad.duikt.edu.ua](https://e-rozklad.duikt.edu.ua/time-table/group)
  (з того самого сайту беруть дані боти розкладу), тож перенесені пари теж підхопить;
- за 2 хвилини до пари відкриває посилання, яке ти заздалегідь вказав для цього предмета;
- заходить з вимкненими мікрофоном і камерою, браузер без звуку;
- якщо ввімкнено зал очікування, чекає, поки впустять;
- виходить **разом з групою**, а не рівно за розкладом: якщо пару відпустили раніше,
  не висітиме в зустрічі сам, а якщо затягнулась — не вийде першим
  (див. [«Коли програма виходить з пари»](#коли-програма-виходить-з-пари));
- [помічник](#помічник-очі-вуха-мозок-і-руки) стежить за парою, поки тебе немає: на перекличці
  відмічається (але ніколи не записує тебе на проєкти); коли тебе кличуть, шле в Telegram відео
  моменту з цитатою; показує чат і пише туди, що ти йому відповіш; після пари надсилає звіт.

## Як це влаштовано

- **Розклад.** Офіційного API в сайту немає. Програма заповнює ту саму форму, що й ти в
  браузері (факультет → курс → група), і читає розклад, який сторінка віддає як JSON.
  Групу вона знаходить сама за назвою.
- **Посилання.** У `config.toml` пишеш правила «предмет (+ тип заняття / викладач) → посилання».
  Якщо для пари правила немає, а викладач вписав посилання на Meet/Zoom прямо в розклад,
  береться воно.
- **Google Meet.** Окремий профіль Chrome, яким керує [Playwright](https://playwright.dev/python/).
  Перед входом програма вимикає мікрофон і камеру й перевіряє, що вони справді вимкнулись.
  Якщо переконатися не вдалося (наприклад, Google змінив інтерфейс), вона забороняє Meet доступ
  до мікрофона й камери на рівні браузера і тільки потім заходить. Увімкнений мікрофон
  на парі неможливий за жодного сценарію.
- **Zoom.** За замовчуванням відкриває Zoom-клієнт напряму (`zoommtg://`), без сторінки
  «Відкрити Zoom?». Мікрофон, камеру й звук вимикають налаштування самого Zoom (див. нижче).
  Інший варіант — веб-версія Zoom у тому ж браузері (`zoom_mode = "browser"`, експериментально).

## Коли програма виходить з пари

Розклад не знає, коли пара закінчиться насправді, але це видно з кількості учасників
зустрічі: наприкінці люди масово виходять. Програма раз на 20 секунд дивиться на лічильник
учасників (значок на кнопці «Учасники» в Meet, лічильник у Zoom) і:

- **пару відпустили раніше** — коли вийшло ~60 % людей, виходить і вона, з випадковою
  паузою 20–60 с, щоб не першою й не останньою;
- **пара затягнулась** — після кінця за розкладом лишається, поки люди не почнуть виходити
  (~30 % вийшло), але не довше ніж `max_overtime_minutes` (20 хв);
- **лишилась сама** — виходить за кілька секунд. На початку пари бути самому нормально, тож
  перші 15 хвилин це правило не діє. Якщо за 15 хвилин так ніхто й не прийшов, вона теж виходить;
- **викладач завершив зустріч** — закриває вкладку;
- **ти сам увімкнув мікрофон** — значить, ти за ноутом, і програма з зустрічі не вийде;
- **починається наступна пара** за іншим посиланням — переходить туди.

Якщо порахувати учасників не вдалося (Google змінив інтерфейс), програма виходить за
розкладом (`leave_after_minutes` після кінця). Вимкнути розумний вихід: `smart_leave = false`.

Нейромережа тут не потрібна: рішення приймається за тими самими цифрами, і прості правила
працюють передбачувано, миттєво й без навантаження на ноут.

## Встановлення

Потрібні **Python 3.11+** ([python.org](https://www.python.org/downloads/); на Windows під час
встановлення постав галочку *Add python.exe to PATH*) і **Google Chrome**.
Для Arch Linux є [окремий розділ](#arch-linux).

```bash
git clone https://github.com/shkbb/lol.git autopara
cd autopara
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate

pip install -e .
playwright install chromium   # запасний браузер, якщо Chrome не знайдеться
```

## Налаштування

1. `config.toml` у репозиторії вже заповнений під Дениса (ТЦР-32): посилання з таблиці групи
   й акаунти. Для когось іншого — скопіюй `config.example.toml` у `config.toml`.
   Секрети (токен Telegram-бота) пиши в `config.local.toml` поруч: він у `.gitignore`
   і накладається поверх `config.toml`.
2. Перевір, що група знаходиться:
   ```
   autopara find-group
   ```
   Програма покаже ID факультету, курсу й групи. Їх можна вписати в `[schedule]`,
   щоб не шукати групу щоразу, але це не обов'язково.
3. Подивись розклад і точні назви предметів:
   ```
   autopara schedule
   ```
   ```
   Пт 02.10  09:30–10:50  Бази даних (Лк)          ✓ Meet: https://meet.google.com/aaa-bbbb-ccc
             11:10–12:30  Англійська мова (Пз)     ✓ Zoom: https://us05web.zoom.us/j/123...
             13:00–14:20  Фізичне виховання (Пз)   — пропускаю
   Сб 03.10  09:30–10:50  Філософія (Лк)           ✗ немає посилання
   ```
4. Впиши посилання в `[[links]]` у `config.toml` (приклади є у файлі) і повтори
   `autopara schedule`. У кожної пари має бути ✓ або «пропускаю».
5. Увійди в Google один раз:
   ```
   autopara login
   ```
   Програма покаже, в які акаунти увійти: основний (`meet_account`) і всі, що вказані в
   посиланнях через `account`. Другий акаунт додається через «Додати обліковий запис».
   Логін зберігається в окремому профілі браузера (`~/.autopara/browser-profile`).
   Zoom-клієнт логіниться окремо, у самому Zoom.
6. Перевір вхід на будь-якій зустрічі. Можна створити свою на [meet.new](https://meet.new):
   ```
   autopara join https://meet.google.com/xxx-xxxx-xxx
   ```
   Програма також напише, чи бачить вона кількість учасників. Від цього залежить
   [розумний вихід](#коли-програма-виходить-з-пари).

### Підгрупи

Якщо лаби йдуть по підгрупах, у розкладі групи в один час стоять дві пари. Щоб брати
саме **свій** розклад, впиши прізвище та ім'я так, як вони записані на сайті:

```toml
[schedule]
student = "Прізвище Ім'я"
```

Список студентів групи показує `autopara find-group --students`. Інший варіант —
правило зі `skip = true` для чужої підгрупи (наприклад, `type = "Лб т.2"`).

### Zoom

З `zoom_mode = "app"` (за замовчуванням) у Zoom-клієнті один раз відкрий **Налаштування**
(Settings). Назви пунктів трохи різняться між версіями:

- **Аудіо (Audio):** «Автоматично підключати звук комп'ютера» (*Automatically join computer audio*),
  «Вимикати мікрофон під час входу» (*Mute my mic when joining*). Щоб не було звуку, поклади
  повзунок гучності динаміка на 0.
- **Відео (Video):** «Вимикати відео під час входу» (*Turn off my video when joining*).

Посилання на Zoom має містити `?pwd=...`, інакше Zoom попросить код доступу.
Персональні посилання на кшталт `zoom.us/my/ім'я` відкриються через браузер.

## Запуск

```
autopara run
```

Програма працює, поки відкрите вікно терміналу. Комп'ютер має бути ввімкнений і **не засинати**
під час пар:

- Linux: програма сама не дає системі заснути від бездіяльності, поки сьогодні ще є пари
  (`systemd-inhibit`). Закрита кришка ноута, як і раніше, присипляє його;
- Windows: *Параметри → Система → Живлення → Перехід у режим сну → Ніколи*;
- macOS: запускай як `caffeinate -i autopara run`.

Лог пишеться в консоль і в `~/.autopara/autopara.log`.

### Автозапуск при вході в систему

**Windows.** Створи `autopara.bat`:

```bat
@echo off
cd /d C:\шлях\до\autopara
.venv\Scripts\autopara.exe run
```

Натисни Win+R → `shell:startup` → поклади туди ярлик на цей файл.

**macOS.** Створи `autopara.command` з такими рядками, виконай `chmod +x autopara.command`
і додай файл у *Системні параметри → Загальні → Об'єкти входу*:

```bash
#!/bin/bash
cd ~/autopara && caffeinate -i .venv/bin/autopara run
```

**Linux.** Див. [Arch Linux](#arch-linux): там є systemd-сервіс і рядки для Hyprland/sway.

## Arch Linux

```bash
sudo pacman -S --needed python git
# Браузер: або Google Chrome з AUR...
yay -S google-chrome
# ...або chromium з офіційних репозиторіїв (тоді в config.toml: browser_path = "/usr/bin/chromium")
sudo pacman -S chromium
# Zoom-клієнт (якщо пари бувають у Zoom)
yay -S zoom

git clone https://github.com/shkbb/lol.git ~/autopara
cd ~/autopara
python -m venv .venv          # на Arch pip поза venv заборонений (PEP 668)
source .venv/bin/activate.fish   # у fish; у bash/zsh — source .venv/bin/activate
pip install -e .
playwright install chromium   # запасний браузер; --with-deps на Arch не потрібен
```

Можна й не активувати venv щоразу, а кликати програму напряму: `~/autopara/.venv/bin/autopara`.

Перевір, що посилання `zoommtg://` відкриваються в Zoom:

```bash
xdg-mime query default x-scheme-handler/zoommtg     # має вивести Zoom.desktop
xdg-mime default Zoom.desktop x-scheme-handler/zoommtg   # якщо вивело порожнє
```

**Автозапуск (GNOME, KDE Plasma, Hyprland через uwsm)** — systemd-сервіс користувача
`~/.config/systemd/user/autopara.service`:

```ini
[Unit]
Description=autopara — автоматичний вхід на пари
After=graphical-session.target
PartOf=graphical-session.target

[Service]
WorkingDirectory=%h/autopara
ExecStart=%h/autopara/.venv/bin/autopara run
Restart=on-failure
RestartSec=30

[Install]
WantedBy=graphical-session.target
```

```bash
systemctl --user daemon-reload
systemctl --user enable --now autopara
journalctl --user -u autopara -f     # лог
```

Якщо в лозі сервісу браузер не запускається через відсутній `DISPLAY`/`WAYLAND_DISPLAY`
(буває на «голих» композиторах), використай варіант нижче.

**Hyprland без uwsm / sway / i3** — просто додай у конфіг композитора:

```
exec-once = cd ~/autopara && .venv/bin/autopara run    # hyprland.conf
exec cd ~/autopara && .venv/bin/autopara run           # sway / i3
```

Скільки це їсть на i5-11320H з 16 ГБ (оцінка):

| що | пам'ять | процесор |
| --- | --- | --- |
| Chrome з однією зустріччю | 1–1,5 ГБ | 5–15 % |
| вуха (whisper `large-v3-turbo`) | ~2 ГБ | ~30–50 %, поки на парі говорять (`small` — ~1 ГБ і ~20 %) |
| мозок (`gemma3:4b`) | ~3,5 ГБ | 100 % на 10–30 с, лише коли щось сталося, плюс конспект раз на кілька хвилин |
| кадри для вирізок | ~10 МБ | 1–3 % |

Разом — до ~7 ГБ, тож решта ноута лишається вільною. На батареї це помітно скорочує час роботи,
тож у дні з парами краще бути на зарядці.

## Помічник: очі, вуха, мозок і руки

Поки тебе немає біля ноута, помічник стежить за парою:

| | що це | звідки |
| --- | --- | --- |
| 👀 очі | чат і кількість учасників | зі сторінки Meet |
| 👂 вуха | що кажуть на парі | звук іде у віртуальний вихід PipeWire, розпізнається локально ([faster-whisper](https://github.com/SYSTRAN/faster-whisper)) |
| ⚡ рефлекси | миттєві правила без ШІ | `autopara/assistant.py` |
| 🧠 мозок | розбирається в ситуаціях, які ми не передбачили | локальна мовна модель через [Ollama](https://ollama.com) |
| ✋ руки | написати в чат, сповістити тебе, вийти | Meet + Telegram-бот |

**Рефлекси** (працюють одразу, навіть без мозку й вух):

- троє й більше людей пишуть у чат «присутній», «тут» чи «дякую» — помічник пише те саме,
  один раз і з паузою між повідомленнями;
- троє й більше людей ставлять **«+»** або пишуть **прізвища** — помічник спершу з'ясовує, **навіщо**
  (див. нижче), і лише на перекличці відповідає сам;
- твоє прізвище чи ім'я прозвучало на парі чи в чаті — термінове сповіщення в Telegram з цитатою,
  а за ~15 секунд — **відеовирізка моменту** (див. нижче);
- викладач оголошує перекличку — сповіщення.

**Коли помічник діє сам.** Розпізнана мова — найслабший сигнал: Whisper може почути «плюс» у
лекції про C++ чи перекрутити «хто хоче проєкт». Тому одна почута фраза **ніколи сама** не запускає
дію в зустрічі. Помічник діє сам, коли **кілька незалежних сигналів** кажуть одне й те саме, а
питає тебе, лише коли вони суперечать один одному або їх бракує.

| ситуація | сигнали | що робить |
| --- | --- | --- |
| група ставить «+», а викладач написав чи **чітко** сказав «хто на парі», «перекличка», «відмітьтесь» в одному реченні з «плюсом» | чат + причина | пише «+» одразу |
| група ставить «+», причину не названо, але мозок перед цим чув перекличку | мозок + чат | пише «+», вистачає двох однокурсників |
| група ставить «+», причину не названо, вуха чітко чули останні хвилини, і ніхто не казав про запис чи голосування | чат + чисте «мовчання» про запис | «Напишу «+» за 45 с, якщо не скажеш «ні»» і пише |
| викладач читає список групи вголос і після кількох прізвищ однокурсників назвав тебе | ≥3 прізвища з розкладу + твоє | пише «Присутній» |
| хтось сказав чи написав про запис, проєкт, доповідь, голосування, «зрозуміло?» | заборона | **ніколи не пише сам**, питає тебе з цитатою |
| причину не названо, а мова навколо розпізнана невпевнено (чи вуха вимкнені) | сигналів бракує | питає тебе |
| мозок чує «перекличку», але в чаті ніхто не відмічається | лише мова | нічого не пише, чекає на групу |
| мозок чує «на сьогодні все» | лише мова | радить вийти; виходить помічник сам за кількістю учасників |
| тебе назвали | лише мова | сповіщення + відео моменту, у чат не пише |

Невпевнено розпізнана мова може лише **заборонити** дію, але не дозволити: якщо почулось щось
схоже на «проєкт», помічник спитає; якщо почулось «хто на парі», цього мало, щоб писати.
Кожна самостійна дія приходить тобі в Telegram разом з цитатою, через яку помічник так вирішив.

**Мозок** отримує опис ситуації (що сказали за останні хвилини, чат, учасники) щоразу, коли
вуха чи очі помітили щось варте уваги («поставте плюс», «увімкніть камери», «здайте до п'ятниці»,
твоє ім'я). Він обирає **одну** дію з короткого списку: нічого / сповістити тебе / написати «+» /
написати прізвище / вийти (лише в другій половині пари). Довільний текст у чат мозок не пише
й на запитання з матеріалу замість тебе не відповідає: для цього він надсилає тобі сповіщення.

**Чого помічник не робить ніколи:** не вмикає мікрофон чи камеру й не пише в чат нічого, крім
«+» на перекличці, твого імені, коротких «присутній/дякую» за групою або тексту, який ти сам
надіслав боту. Якщо хочеш, щоб він питав дозволу навіть на перекличці, постав `[me] chat_reply = "ask"`.

**Відеовирізка моменту.** Коли тебе згадали, помічник одразу шле коротке сповіщення, а за ~15 секунд
(щоб було видно, що спитали далі) — відео приблизно хвилини: 45 секунд до згадки і 15 після.
У ньому сторінка зустрічі разом з чатом, звук пари і детальна цитата з розшифровки в підписі.
Кадри знімаються з самої вкладки (2–3 на секунду), тож ноут не навантажується. Потрібен `ffmpeg`
(`sudo pacman -S ffmpeg`). Без нього прийде останній кадр і цитата, а без вух — відео без звуку.
Вимкнути вирізки: `[telegram] clips = false`.

**Звіт після пари.** Коли пара закінчується, приходить вижимка: про що була, що робили, завдання
й дедлайни, чи тебе згадували і що помічник писав у чат. До неї додається файл з повною
розшифровкою і чатом. Мозок конспектує розшифровку частинами ще під часу пари, коли не зайнятий
важливішим, тому звіт приходить за хвилину-дві після кінця. Без мозку звіт містить статистику,
згадки й файл, але без підсумку. Розшифровки зберігаються лише локально, у `~/.autopara/transcripts`.

### Telegram

1. У Telegram напиши [@BotFather](https://t.me/BotFather) → `/newbot` → придумай назву. Він дасть токен.
2. Створи `config.local.toml` поруч з `config.toml`:
   ```toml
   [telegram]
   token = "123456:ABC..."
   ```
3. `autopara telegram` → напиши боту будь-що → програма покаже `chat_id`, допиши його туди ж.
   Бот слухає команди лише з твого чату.

Що можна писати боту під час пари:

| команда | що зробить |
| --- | --- |
| `статус` | яка пара, скільки до кінця, скільки учасників, що кажуть і пишуть |
| `чат` | останні 20 повідомлень чату зустрічі (разом з тими, що були до твого приходу) |
| `екран` | скріншот зустрічі |
| `так` / `ні` | відповідь на «написати «+» у чат?» |
| `+` | написати «+» у чат |
| `напиши <текст>` | написати твій текст у чат (наприклад, «напиши Вибачте, пропав зв'язок») |
| ↩️ відповідь на будь-яке повідомлення бота | твій текст піде в чат пари: відповідаєш на «тебе кличуть» чи на `чат` — і готово |
| `вийди` | вийти з пари |

Слова-команди (`так`, `ні`, `статус`…) лишаються командами навіть у відповіді. Щоб написати в чат
саме «так», надішли `напиши так`.

### Вуха (Arch Linux)

```bash
sudo pacman -S --needed pipewire-pulse libpulse ffmpeg   # libpulse дає pactl і parec
source .venv/bin/activate.fish
pip install -e ".[ears]"
```

У `config.toml`: `[ears] enabled = true`. Звук пари йде у віртуальний вихід `autopara`, і вуха
слухають його звідти.

**Як розпізнається мова.** Це [Whisper](https://github.com/openai/whisper) — модель розпізнавання
мови від OpenAI, запущена локально через [faster-whisper](https://github.com/SYSTRAN/faster-whisper)
на процесорі ноута, без інтернету. Мова примусово українська, тиша відсікається (Silero VAD), а звук
розпізнається шматками по 10 секунд. Щоб помилок було менше і вони нічого не ламали:

- **модель**: `large-v3-turbo` (у твоєму конфігу) значно точніша за `small`, особливо в прізвищах
  і термінах. Важить ~1,6 ГБ, завантажується при першому запуску. Якщо ноут не встигатиме
  розпізнавати в реальному часі, програма сама перейде на `small` і напише про це;
- **підказка**: Whisper отримує твоє ім'я, ім'я викладача й назву пари, тож рідше їх перекручує;
- **впевненість**: для кожного шматка Whisper сам оцінює, наскільки він певен. Невпевнене
  позначається `[?]` у звіті й для мозку і ніколи не дозволяє дій;
- **фільтри**: відкидаються типові «галюцинації» Whisper на тиші («Дякую за перегляд!», «Субтитри…»)
  і випадки, коли модель просто повторює підказку.

Порівняти моделі на справжньому звуці (увімкни на ноуті, наприклад, лекцію українською на YouTube):

```bash
autopara listen-test --models small,large-v3-turbo
```

Команда покаже, що розпізнала кожна модель, де вона не впевнена (`[?]`) і чи встигає за мовою.
Чи чуєш пару ти, вирішує `[join] mute_sound`:

- `mute_sound = false` — звук дублюється ще й у динаміки чи навушники (і сам перемикається, коли
  їх підключаєш). У налаштуваннях звуку GNOME цей дубль видно як окремий потік, і його гучність
  можна крутити окремо;
- `mute_sound = true` — у динаміках тиша, чують лише вуха.

Мова розпізнається локально й нікуди не надсилається. Розшифровка пари зберігається лише в
`~/.autopara/transcripts` для звіту.

### Мозок (Arch Linux)

```bash
sudo pacman -S ollama
sudo systemctl enable --now ollama
ollama pull gemma3:4b
```

У `config.toml`: `[brain] enabled = true`. Модель займає ~3,5 ГБ пам'яті, а на i5 11-го покоління
одне рішення займає 10–30 секунд. Тому її кличуть лише тоді, коли вуха чи очі щось помітили,
а термінові речі (тебе назвали, група пише «+») обробляють миттєві рефлекси.
Якщо в репозиторії Arch є збірка Ollama з Vulkan, на Iris Xe вона працюватиме швидше.
Можна взяти іншу модель (`model = "qwen3:4b"` тощо). Головне, щоб вона добре розуміла українську.

### Перевірка

```bash
autopara check                                     # що налаштовано, а що ні
autopara join https://meet.google.com/xxx-xxxx-xxx  # тестова зустріч (створи на meet.new)
```

`join` працює так само, як на справжній парі: показує, скільки учасників бачить, а з `-v` —
що чують вуха. Напиши боту з телефона `напиши тест`, і повідомлення з'явиться в чаті зустрічі.

## Обмеження

- Інтерфейс Meet і Zoom змінюється. Якщо програма не змогла переконатися, що мікрофон
  вимкнений, вона все одно зайде, але з заблокованими мікрофоном і камерою, і напише про це
  в лог. Щоб на такій парі говорити, закрий вкладку й зайди вручну.
- Поки `mute_sound = true`, у динаміках тиша. Щоб слухати пару, постав `mute_sound = false`
  і перезапусти програму.
- На питання викладача помічник замість тебе не відповідає — лише кличе тебе й показує момент.
- Чат Meet програма читає за розміткою сторінки, перевіреною лише на імітації. Якщо після
  `autopara join` боту не вдається написати в чат, скинь лог, і розмітку поправимо.
- Вуха працюють лише на Linux з PipeWire/PulseAudio і слухають лише браузер (не Zoom-клієнт).
- Розумний вихід бачить учасників лише в браузері. З Zoom-клієнтом (`zoom_mode = "app"`)
  програма його не контролює: зазвичай викладач завершує конференцію для всіх, і Zoom
  закривається сам. Якщо хочеш розумний вихід і в Zoom — постав `zoom_mode = "browser"`.
- Сайт розкладу не має офіційного API. Якщо його переробять, `autopara schedule` покаже
  помилку, і треба буде оновити `autopara/rozklad.py`.
- Посилання в самому розкладі викладачі заповнюють не завжди, тому краще вписати свої в `[[links]]`.

## Для розробки

```bash
pip install -e ".[dev]"
pytest
```

Тести перевіряють розбір сайту розкладу (на імітації його відповідей), планування пар,
фоновий цикл, а також логіку входу в Meet і Zoom у справжньому Chromium на тестових
сторінках, що імітують розмітку Meet/Zoom.

| Файл | Що робить |
| --- | --- |
| `autopara/rozklad.py` | клієнт сайту розкладу: форма, CSRF, розбір `var events` |
| `autopara/links.py` | правила посилань, посилання Meet/Zoom |
| `autopara/planner.py` | розклад → список «візитів» (коли зайти і вийти) |
| `autopara/joiner.py` | вхід у Meet/Zoom з вимкненими мікрофоном і камерою, підрахунок учасників |
| `autopara/leaving.py` | коли виходити: разом з групою, а не за розкладом |
| `autopara/assistant.py` | помічник: рефлекси, правила безпеки, команди з Telegram |
| `autopara/brain.py` | мозок: локальна мовна модель через Ollama |
| `autopara/ears.py` | вуха: віртуальний аудіовихід + розпізнавання мови |
| `autopara/telegram.py` | Telegram-бот і сповіщення на робочий стіл |
| `autopara/media.py` | відеовирізки моментів: кадри сторінки + звук → ffmpeg |
| `autopara/report.py` | звіт після пари й файл з розшифровкою |
| `autopara/wiring.py` | збирає помічника відповідно до конфіга |
| `autopara/power.py` | не дає ноуту заснути, поки сьогодні є пари (Linux) |
| `autopara/runner.py` | фоновий цикл |
| `autopara/cli.py` | команди `find-group`, `schedule`, `login`, `join`, `run`, `telegram`, `check` |

Формат форми розкладу підглянуто у відкритому застосунку
[KyivSec/DuiktTimetable](https://github.com/KyivSec/DuiktTimetable).
