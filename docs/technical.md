# autopara — технічні подробиці

Як усе влаштовано, налаштування у файлі, командний рядок, ресурси, Linux-дрібниці й розробка.
Щоб просто користуватися, досить [README](../README.md).

## Як це влаштовано

- **Розклад.** ДУІКТ: офіційного API в сайту немає, тож програма заповнює ту саму форму, що й
  ти в браузері (факультет → курс → група), і читає розклад, який сторінка віддає як JSON.
  КПІ: відкритий API, яким користується сам schedule.kpi.ua (двотижневий цикл враховується).
  Групу програма знаходить за назвою; для КПІ можна просто вставити посилання на розклад групи.
- **Посилання.** Правила «предмет (+ тип заняття / викладач) → посилання» задаються у вкладці
  «Налаштування» → «Пари»: програма показує предмети з твого розкладу, лишається вставити посилання.
  Якщо для пари правила немає, а викладач вписав посилання на Meet/Zoom прямо в розклад,
  береться воно.
- **Браузер.** Свій у програми: вбудований Chromium від [Playwright](https://playwright.dev/python/) з окремим
  профілем, тож Chrome чи інший браузер не потрібен. Інсталятор ставить його одразу, а якщо не вийшло — програма
  докачує сама (`browser_setup.py`). Окремого вікна браузер не має: Chromium працює невидимо (новий headless —
  той самий Chrome, з відеокартою й підписом звичайного Chrome), а сторінка «Браузер» у вікні програми показує
  вибрану вкладку трансляцією CDP (`Page.startScreencast`, до 15 кадрів/с, лише поки сторінку видно) і передає
  їй мишку, колесо, клавіатуру й буфер обміну (`screen.py`, `gui/browser.py`). Запускається браузер лише на час
  пари чи входу в Google і закривається, щойно пара скінчилась. Для розробки `AUTOPARA_BROWSER_WINDOW=1` дає
  звичайне вікно, а `autopara login` і `autopara join` (без вікна програми) відкривають його завжди.
- **Google Meet.**
  Перед входом програма вимикає мікрофон і камеру й перевіряє, що вони справді вимкнулись.
  Якщо переконатися не вдалося (наприклад, Google змінив інтерфейс), вона забороняє Meet доступ
  до мікрофона й камери на рівні браузера і тільки потім заходить. Увімкнений мікрофон
  на парі неможливий за жодного сценарію.
  Вхід у сам браузер у цьому профілі програма вимикає, тож університетська пошта (Google Workspace)
  входить як на звичайному сайті й не переїжджає в окремий профіль. У які акаунти увійдено, програма бачить
  сама (запит `ListAccounts` з кукі профілю, без вкладки) і основним бере університетський.
- **Zoom.** Сам вибирає спосіб: Zoom-клієнт напряму (`zoommtg://`, без сторінки «Відкрити Zoom?»),
  якщо вуха можуть його чути (Linux або віртуальний кабель), інакше — веб-версію Zoom у тому ж
  браузері; якщо там не пустили — таки клієнт, і посилання запам'ятовується. У клієнті мікрофон,
  камеру й звук вимикають налаштування самого Zoom (див. нижче).
- **Вікно програми** — звичайна програма на Qt (PySide6) для Linux, Windows і macOS. Вона
  викликає функції `app.api_*` напряму; повільне (сайт розкладу, Telegram) — у фоновому потоці.
  Закрив вікно — програма працює далі у фоні. Ярлик лише показує вікно: друга копія не
  запускається, а просить уже запущену показати себе через локальний API (лише 127.0.0.1,
  з випадковим токеном і перевіркою Host).

## Коли програма виходить з пари

Розклад не знає, коли пара закінчиться насправді, але це видно з кількості учасників
зустрічі: наприкінці люди масово виходять. Програма раз на 20 секунд дивиться на лічильник
учасників (значок на кнопці «Учасники» в Meet, лічильник у Zoom) і:

- **пару відпустили раніше** — коли вийшло ~60 % людей, виходить і вона, з випадковою
  паузою 20–60 с, щоб не першою й не останньою;
- **пара затягнулась** — після кінця за розкладом лишається, поки люди не почнуть виходити
  (~30 % вийшло), але не довше ніж `max_overtime_minutes` (20 хв);
- **лишилась сама** — виходить за кілька секунд. На початку пари бути самому нормально, тож
  перші 15 хвилин це правило не діє. Якщо за 15 хвилин так ніхто й не прийшов, вона теж виходить;
- **викладач завершив зустріч** — закриває вкладку;
- **ти сам увімкнув мікрофон** — значить, ти за ноутом, і програма з зустрічі не вийде;
- **починається наступна пара** за іншим посиланням — переходить туди.

Якщо порахувати учасників не вдалося (Google змінив інтерфейс), програма виходить за
розкладом (`leave_after_minutes` після кінця). Вимкнути розумний вихід: `smart_leave = false`.

Нейромережа тут не потрібна: рішення приймається за тими самими цифрами, і прості правила
працюють передбачувано, миттєво й без навантаження на ноут.

## Встановлення вручну, без скрипта

Потрібен **Python 3.11+**.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate     macOS / Linux: source .venv/bin/activate
pip install -e ".[ears]"                       # без [ears] — без розпізнавання мови (доставити можна кнопкою у вікні)
python -m playwright install chromium --no-shell   # браузер програми (інакше програма завантажить його сама)
autopara app
```

На Linux у сесії X11 Qt потрібна бібліотека `libxcb-cursor` (Ubuntu: `sudo apt install libxcb-cursor0`).

## Налаштування

### Що можна вимкнути

Усе, що програма робить сама, вимикається окремо:

| де у вікні | що | якщо вимкнути |
| --- | --- | --- |
| Сьогодні | автоматичний вхід на пари | програма нікуди не заходить, поки не ввімкнеш |
| Налаштування → Помічник → «Писати в чат пари самому» | будь-які повідомлення в чат пари | «лише після мого «так»» — питає щоразу, «ніколи» — лише сповіщає |
| Налаштування → Помічник → «Більше налаштувань» | відмітка на перекличці, «Так, я тут», «Дякую»/«Добрий день» за групою | перекличка й «ви тут?» — лише питає тебе, ввічливості — мовчить |
| Налаштування → Помічник | вуха, мозок | не слухає пару / без мовної моделі |
| Налаштування → Telegram → «Що бот робить» | відповіді на команди й кнопки | бот лише надсилає сповіщення і нічого не відповідає |
| Налаштування → Telegram | сповіщення про згадки, відеовирізки, звіт після пари, «зайшов/вийшов» | не надсилає саме цього (невдалий вхід — повідомляє завжди) |
| Налаштування → Загальне | вимикати мікрофон/камеру/звук, виходити разом з групою, автозапуск (виходити самому — «Більше налаштувань») | |

Без відповідей бота помічник не може тебе спитати. Тоді там, де він питав би, він лише
сповіщає й сам не пише. Самостійно діє лише за надійних сигналів (перекличку назвали прямо).

Налаштування зберігаються в теці користувача:
Linux — `~/.config/autopara/config.toml`, Windows — `%APPDATA%\autopara\config.toml`,
macOS — `~/Library/Application Support/autopara/config.toml`.
Профіль браузера з логіном Google і журнал — у `~/.autopara`.

### Для Дениса

Твої дані (ТЦР-32, «Ляшко Денис», посилання з таблиці куратора, три акаунти, Zoom, вуха й
мозок) збережені в `profiles/group.toml`. Один раз після оновлення:

```bash
cd ~/autopara && git pull
./install.sh                                      # доставить нові залежності (вуха, ffmpeg) і ярлик
.venv/bin/autopara import-config profiles/group.toml
```

`import-config` переносить і токен бота з `config.local.toml`, якщо запустити його з теки
репозиторію. Якщо autopara вже працює як сервіс, вона підхопить налаштування одразу, без
перезапуску. Те саме можна зробити кнопкою «Профіль «profile»» у «Налаштування» → «Загальне»
(токен бота тоді збережеться той, що вже був налаштований).

### Без вікна

Усе те саме можна робити з командного рядка і в файлі налаштувань (зразок — `config.example.toml`):

```
autopara find-group [--students]  # знайти групу ДУІКТ і показати ID / список студентів
autopara schedule [--date 07.10]  # розклад і які посилання відкриються
autopara login                    # увійти в Google у звичайному вікні браузера (поки програма не запущена)
autopara join <посилання>         # тестовий вхід
autopara check                    # що налаштовано, а що ні
```

```
Пт 02.10  09:30–10:50  Бази даних (Лк)          ✓ Meet: https://meet.google.com/aaa-bbbb-ccc
          11:10–12:30  Англійська мова (Пз)     ✓ Zoom: https://us05web.zoom.us/j/123...
          13:00–14:20  Фізичне виховання (Пз)   — пропускаю
Сб 03.10  09:30–10:50  Філософія (Лк)           ✗ немає посилання
```

### Zoom

Якщо пари бувають у Zoom-клієнті, у ньому один раз відкрий **Налаштування**
(Settings). Назви пунктів трохи різняться між версіями:

- **Аудіо (Audio):** «Автоматично підключати звук комп'ютера» (*Automatically join computer audio*),
  «Вимикати мікрофон під час входу» (*Mute my mic when joining*). Щоб не було звуку, поклади
  повзунок гучності динаміка на 0.
- **Відео (Video):** «Вимикати відео під час входу» (*Turn off my video when joining*).

Посилання на Zoom має містити `?pwd=...`, інакше Zoom попросить код доступу.
Персональні посилання на кшталт `zoom.us/my/ім'я` відкриються через браузер.

## Запуск

- `autopara app` — програма з вікном. Закрив вікно — програма працює далі у фоні (значок у треї, якщо
  система його показує); `autopara app` чи ярлик ще раз просто показують вікно.
- `autopara app --hidden` — так програму запускає автозапуск: працює, а вікно не показує.
- `autopara run` — без вікна взагалі (сервер, systemd). Вікна в такої копії немає.

Друга копія програми не запуститься: дві копії заходили б на пару двічі.

**Автозапуск**: майстер вмикає його сам, вимкнути — «Налаштування» → «Загальне». На Windows це запис у
реєстрі (без вікна консолі), на Linux — `~/.config/autostart`, на macOS — LaunchAgent. Якщо на Linux вже є
systemd-сервіс (див. [Arch Linux](#arch-linux)), перемикач це покаже й нічого не додасть.

Комп'ютер має бути ввімкнений, а програма сама не дає йому **заснути** від бездіяльності, поки
сьогодні ще є пари (Linux — `systemd-inhibit`, Windows — `SetThreadExecutionState`, macOS —
`caffeinate`). Закрита кришка ноутбука, як і раніше, присипляє його.

Журнал видно в розділі «Журнал» (унизу бічного меню), а також у `~/.autopara/autopara.log`.

## Скільки ресурсів це їсть

Оцінка для ноутбука на кшталт i5-11320H з 16 ГБ. «Налаштування» → «Помічник» → «Більше налаштувань» рахує те саме для твоїх
налаштувань.

| що | пам'ять | процесор |
| --- | --- | --- |
| браузер програми з однією зустріччю | 1–1,5 ГБ | 10–25 % під час пари, ще ~20 %, поки пару видно у вікні |
| сама програма, вікно налаштувань (поки відкрите) | ~0,15 ГБ + ~0,2 ГБ | майже 0 |
| вуха: whisper `small` / `large-v3-turbo` | ~1 / ~2 ГБ | 20 / 30–50 %, поки на парі говорять |
| мозок: `gemma3:4b` через Ollama | ~3,5–4 ГБ | 100 % на 10–30 с, коли щось сталося, плюс конспект раз на кілька хвилин |
| кадри для відеовирізок | ~10 МБ | 1–3 % |

- **Лише автовхід** (без вух і мозку): ~1,5 ГБ і 10–25 % процесора під час пари.
- **Усе ввімкнено**: ~6–7 ГБ під час пари, решта ноутбука лишається вільною. Між парами
  програма майже нічого не їсть, а Ollama сама вивантажує модель після 5 хвилин простою.
- **Диск**: whisper `small` — 0,5 ГБ, `large-v3-turbo` — 1,6 ГБ, `gemma3:4b` — 3,3 ГБ, профіль
  браузера — кілька сотень МБ.
- **Батарея**: з вухами й мозком ноутбук сідає помітно швидше, у дні з парами краще бути на зарядці.

## Windows

Працює все те саме, що й на Linux, зокрема вуха, звіти й сповіщення. Windows-частини перевірені
тестами, але на справжньому Windows програму ще ніхто не запускав — якщо щось не так, скинь
вкладку «Журнал».

| | Windows |
| --- | --- |
| розклад, вікно програми, автовхід у Meet і Zoom, розумний вихід | ✓ |
| Telegram: сповіщення, кнопки, «напиши …», чат, скріншоти, звіт після пари | ✓ |
| вуха: розпізнавання мови, голосова перекличка, розшифровка для звіту | ✓ — Meet і Zoom у браузері одразу; Zoom-клієнт — з віртуальним кабелем ([див. «Вуха»](#вуха)), без нього Zoom сам відкриється в браузері |
| мозок (Ollama) | ✓ — встанови [Ollama](https://ollama.com/download), решту програма зробить сама |
| відеовирізки зі звуком | ✓ — ffmpeg іде разом із програмою |
| сповіщення на робочий стіл | ✓ — звичайні сповіщення Windows |
| не засинати під час пар, автозапуск | ✓ |

Встановлення: розпакуй архів і двічі клацни `install.bat`. Якщо Windows спитає «Захистила
ваш ПК» — «Докладніше» → «Однаково запустити». На робочому столі з'явиться ярлик «autopara»
(він відкриває програму без чорного вікна консолі).

**macOS** має працювати так само, як Windows (на Mac програму ще не перевіряли): `./install.sh`,
ярлик — `~/Applications/autopara.command`.

## Поділитися з друзями

Найпростіше — архів без особистих даних:

```bash
git archive --format=zip -o autopara.zip HEAD
```

Тека `profiles/` у нього не потрапляє (так налаштовано в `.gitattributes`; так само працює
«Download ZIP» на GitHub). Якщо даєш доступ до самого репозиторію, спершу прибери з нього
`profiles/group.toml`: там твої посилання на пари й пошти.

Другові: розпакувати й запустити інсталятор (див. [README](../README.md)) — далі простий майстер,
включно з його власним Telegram-ботом.
Свої налаштування він може передати іншому одногрупнику файлом `config.toml` з теки
налаштувань: у того в «Налаштування» → «Загальне» є кнопка «Імпорт з файла…». Токен Telegram-бота
у файлі особистий — його перед передачею краще стерти.

## Arch Linux

```bash
sudo pacman -S --needed python git libpulse   # libpulse (pactl) — щоб вуха чули Zoom-клієнт
yay -S zoom                                   # Zoom-клієнт, якщо пари бувають у Zoom (або Flatpak us.zoom.Zoom)
sudo pacman -S ollama && sudo systemctl enable --now ollama   # мозок (за бажанням; на Iris Xe є ollama-vulkan)

git clone https://github.com/shkbb/lol.git ~/autopara
cd ~/autopara && ./install.sh                 # venv (PEP 668), браузер програми, ярлик у меню
```

Браузер ставити не треба — у програми свій. Перевір, що посилання `zoommtg://` відкриваються в Zoom:

```bash
xdg-mime query default x-scheme-handler/zoommtg     # має вивести Zoom.desktop (чи us.zoom.Zoom.desktop)
xdg-mime default Zoom.desktop x-scheme-handler/zoommtg   # якщо вивело порожнє
```

**systemd замість автозапуску GNOME** (для «голих» композиторів) — сервіс користувача
`~/.config/systemd/user/autopara.service` з `ExecStart=%h/autopara/.venv/bin/autopara run`
(`WantedBy=graphical-session.target`), потім `systemctl --user enable --now autopara`. Така копія
працює без вікна. **Hyprland / sway / i3** — `exec-once = ~/autopara/.venv/bin/autopara app --hidden`.

## Помічник: очі, вуха, мозок і руки

Поки тебе немає біля ноута, помічник стежить за парою:

| | що це | звідки |
| --- | --- | --- |
| 👀 очі | чат і кількість учасників | зі сторінки Meet |
| 👂 вуха | що кажуть на парі | звук лише вкладки пари чи Zoom-клієнта, розпізнається локально ([faster-whisper](https://github.com/SYSTRAN/faster-whisper)) |
| ⚡ рефлекси | миттєві правила без ШІ | `autopara/assistant.py` |
| 🧠 мозок | розбирається в ситуаціях, які ми не передбачили | локальна мовна модель через [Ollama](https://ollama.com) |
| ✋ руки | написати в чат, сповістити тебе, вийти | Meet + Telegram-бот |

**Рефлекси** (працюють одразу, навіть без мозку й вух):

- троє й більше людей пишуть у чат «присутній», «тут» чи «дякую» — помічник пише те саме,
  один раз і з паузою між повідомленнями;
- троє й більше людей ставлять **«+»** або пишуть **прізвища** — помічник спершу з'ясовує, **навіщо**
  (див. нижче), і лише на перекличці відповідає сам;
- твоє прізвище чи ім'я прозвучало на парі чи в чаті — термінове сповіщення в Telegram з цитатою,
  а за ~15 секунд — **відеовирізка моменту** (див. нижче);
- викладач оголошує перекличку — сповіщення.

**Коли помічник діє сам.** Розпізнана мова — найслабший сигнал: Whisper може почути «плюс» у
лекції про C++ чи перекрутити «хто хоче проєкт». Тому одна почута фраза **ніколи сама** не запускає
дію в зустрічі. Помічник діє сам, коли **кілька незалежних сигналів** кажуть одне й те саме, а
питає тебе, лише коли вони суперечать один одному або їх бракує.

| ситуація | сигнали | що робить |
| --- | --- | --- |
| група ставить «+», а викладач написав чи **чітко** сказав «хто на парі», «перекличка», «відмітьтесь» в одному реченні з «плюсом» | чат + причина | пише «+» одразу |
| група ставить «+», причину не названо, але мозок перед цим чув перекличку | мозок + чат | пише «+», вистачає двох однокурсників |
| група ставить «+», причину не названо, вуха чітко чули останні хвилини, і ніхто не казав про запис чи голосування | чат + чисте «мовчання» про запис | «Напишу «+» за 45 с, якщо не скажеш «ні»» і пише |
| викладач читає список групи, на прізвища однокурсників відповідають «є», «тут» (голосом чи «+» у чаті), і назвали тебе | прізвища зі списку групи + відповіді людей | пише «Присутній» |
| викладач питає саме тебе: «Ляшко, ви тут?», «чуєте?» (розпізнано чітко) | твоє прізвище + питання про присутність | пише «Так, я тут» і кличе тебе |
| звучать прізвища разом з твоїм, але ніхто не відповідає «є», або поруч «не здали», «борги», «доповіді» | схоже на перелік боржників чи розподіл тем | **не пише**, питає тебе з кнопкою |
| «плюс, якщо мене чути / бачите екран» | перевірка зв'язку | пише «+» |
| хтось сказав чи написав про запис, проєкт, доповідь, голосування, «зрозуміло?» | заборона | **ніколи не пише сам**, питає тебе з цитатою |
| причину не названо, а мова навколо розпізнана невпевнено (чи вуха вимкнені) | сигналів бракує | питає тебе |
| мозок чує «перекличку», але в чаті ніхто не відмічається | лише мова | нічого не пише, чекає на групу |
| мозок чує «на сьогодні все» | лише мова | радить вийти; виходить помічник сам за кількістю учасників |
| тебе назвали з питанням по темі («Ляшко, яка складність…?») | лише мова | сповіщення з кнопками + відео моменту, сам не відповідає |

Невпевнено розпізнана мова може лише **заборонити** дію, але не дозволити: якщо почулось щось
схоже на «проєкт», помічник спитає; якщо почулось «хто на парі», цього мало, щоб писати.
Кожна самостійна дія приходить тобі в Telegram разом з цитатою, через яку помічник так вирішив.

**Жива мова.** На парі говорять не як у підручнику: українська вперемішку з суржиком і російською,
англіцизми («запуште на гіт», «дедлайн», «ріквест»), репліки обриваються, кілька людей говорять
одночасно, частина відповідає голосом, частина — в чат. Що з цим робить програма:

- **розпізнавання**: Whisper тренований на сотнях тисяч годин мовлення багатьма мовами, зокрема
  українською й російською. З примусовою українською він передає суржик українськими літерами,
  а англійські терміни — латиницею або транслітом. Рідкісні терміни, імена й нечіткий звук він
  перекручує — це нормально, і на точних словах нічого важливого не тримається;
- **слова-підказки** (перекличка, запис, борги, «чути?») — українською, суржиком і російською,
  але вони лише підказують, а не вирішують;
- **вирішує поведінка людей**, бо її розпізнати надійніше, ніж слова: чи ставлять однокурсники «+»,
  чи відповідають «є» на прізвища, скільки людей лишилось у зустрічі. Перелік боржників звучить
  так само, як перекличка, але на нього ніхто не відповідає «тут»;
- **сенс розмови** розбирає мозок: йому прямо пояснено, чим перекличка відрізняється від переліку
  боржників, запису на доповідь, голосування чи «плюс, якщо зрозуміло», і він має процитувати фразу,
  на яку спирається;
- **де ризиковано — вирішуєш ти, одним дотиком**: кожне питання приходить з кнопками
  («✅ Написати «+»» / «❌ Ні»), а сповіщення «тебе кличуть» — з готовими відповідями
  («Присутній», «Так, я тут»; свої — в `[me] quick_replies`) і кнопками «Чат» та «Екран».

Повної автономії в людських розмовах не дасть жодна програма. Тому помічник діє сам там, де помилка
дешева або сигнали надійні (перекличка, перевірка зв'язку, вихід з пари), а там, де помилка дорого
коштує (запис на проєкт, заява «я вже здав», відповідь по темі), — зупиняється й питає тебе.

**Мозок** отримує опис ситуації (що сказали за останні хвилини, чат, учасники) щоразу, коли
вуха чи очі помітили щось варте уваги («поставте плюс», «увімкніть камери», «здайте до п'ятниці»,
твоє ім'я). Він обирає **одну** дію з короткого списку: нічого / сповістити тебе / написати «+» /
написати прізвище / вийти (лише в другій половині пари). Довільний текст у чат мозок не пише
й на запитання з матеріалу замість тебе не відповідає: для цього він надсилає тобі сповіщення.

**Чого помічник не робить ніколи:** не вмикає мікрофон чи камеру й не пише в чат нічого, крім
«+» на перекличці, твого імені, коротких «присутній/дякую» за групою або тексту, який ти сам
надіслав боту. Якщо хочеш, щоб він питав дозволу навіть на перекличці, постав `[me] chat_reply = "ask"`.

**Відеовирізка моменту.** Коли тебе згадали, помічник одразу шле коротке сповіщення, а за ~15 секунд
(щоб було видно, що спитали далі) — відео приблизно хвилини: 45 секунд до згадки і 15 після.
У ньому сторінка зустрічі разом з чатом, звук пари і детальна цитата з розшифровки в підписі.
Кадри знімаються з самої вкладки (2–3 на секунду), тож ноут не навантажується. ffmpeg іде разом
із програмою (якщо в системі є свій — береться він). Без вух — відео без звуку.
Вимкнути вирізки: `[telegram] clips = false`.

**Звіт після пари.** Коли пара закінчується, приходить вижимка: про що була, що робили, завдання
й дедлайни, чи тебе згадували і що помічник писав у чат. До неї додається файл з повною
розшифровкою і чатом. Мозок конспектує розшифровку частинами ще під часу пари, коли не зайнятий
важливішим, тому звіт приходить за хвилину-дві після кінця. Без мозку звіт містить статистику,
згадки й файл, але без підсумку. Розшифровки зберігаються лише локально, у `~/.autopara/transcripts`.

### Telegram

У кожного свій бот, і створюється він за хвилину («Налаштування» → «Telegram» веде крок за кроком):

1. У Telegram відкрий [@BotFather](https://t.me/BotFather) → `/newbot` → назва будь-яка, ім'я
   латиницею й закінчується на `bot`. Він пришле токен.
2. Встав токен у вікні → «Перевірити» → програма покаже `@ім'я_бота`.
3. «Підключити» → відкриється твій бот → натисни «Start». Telegram на телефоні? Знайди бота там
   і надішли йому шестизначний код, який показує вікно. Бот привітається, налаштування збережуться.

Сповіщення отримує лише той, хто надіслав код, і бот слухає команди лише з його чату. Випадковий
перехожий, що знайшов бота, коду не знає. Без вікна: токен у `[telegram] token = "..."`,
потім `autopara telegram`.

**Чому не один спільний бот на всіх.** Telegram віддає повідомлення бота лише одній програмі:
дві копії з тим самим токеном отримують помилку «409 Conflict» і крадуть одна в одної
повідомлення. До того ж хто має токен, той читає все, що пишуть боту всі користувачі, і може
писати від його імені — тобто друзі бачили б кнопки й відповіді одне одного. Спільний бот
можливий лише з сервером посередині, що працює цілодобово, тримає токен і розсилає кожному його
повідомлення. Але тоді власник сервера бачить звіти й вирізки всіх. Тож свій бот на кожного —
і простіше, і приватніше.

Що можна писати боту під час пари:

| команда | що зробить |
| --- | --- |
| `статус` | яка пара, скільки до кінця, скільки учасників, що кажуть і пишуть |
| `чат` | останні 20 повідомлень чату зустрічі (разом з тими, що були до твого приходу) |
| `екран` | скріншот зустрічі |
| `так` / `ні` | відповідь на «написати «+» у чат?» (або кнопки під питанням) |
| `+` | написати «+» у чат |
| `напиши <текст>` | написати твій текст у чат (наприклад, «напиши Вибачте, пропав зв'язок») |
| ↩️ відповідь на будь-яке повідомлення бота | твій текст піде в чат пари: відповідаєш на «тебе кличуть» чи на `чат` — і готово |
| `вийди` | вийти з пари |

Слова-команди (`так`, `ні`, `статус`…) лишаються командами навіть у відповіді. Щоб написати в чат
саме «так», надішли `напиши так`.

### Вуха

Ставить їх `install.sh` / `install.bat` (або кнопка «Встановити розпізнавання мови» у вікні).
Щоб на Linux вуха чули Zoom-клієнт, потрібен `pactl` (на Arch: `sudo pacman -S --needed libpulse`,
зазвичай він уже є).

У вікні: «Налаштування» → «Помічник» → «Слухати пару» (у файлі — `[ears] enabled = true`). Вуха чують пари і в
Meet, і в Zoom, і **лише пари**:

| пара | звідки звук | налаштувати |
| --- | --- | --- |
| Meet, Zoom у браузері (будь-яка ОС) | лише з вкладки, де програма сама зайшла на пару: маленький скрипт підключається до голосів учасників (тих самих, що грають у динаміках). Працює й із вимкненим звуком, мікрофон не чіпає | нічого |
| Zoom-клієнт, Linux | на час пари програма переносить у віртуальний вихід PipeWire/PulseAudio **лише потоки Zoom**, а після пари повертає їх у навушники чи динаміки | нічого |
| Zoom-клієнт, Windows / macOS | віртуальний аудіокабель, у який Zoom виводить звук | один раз, див. нижче |

**Що вуха не чують.** YouTube, музику, ігри, інший браузер — ні в розпізнавання, ні у відеовирізки
вони не потрапляють, навіть якщо відкрити YouTube у самому вікні браузера програми (скрипт працює
лише на сторінках Meet і Zoom і лише у вкладці пари). Кадри для вирізок теж знімаються тільки з
вкладки пари. Порада: у вікні браузера програми нічого стороннього не відкривай — якщо вкладка пари
опиниться у фоні, браузер перестає її малювати, і у вирізці буде застиглий кадр (звук лишиться).
Запасний шлях на Linux — «Пари в браузері: звідки брати звук» → «весь звук браузера програми»
(`[ears] source = "pulse"`): він чує всі вкладки браузера програми, тож там YouTube потрапив би.

**Zoom-клієнт на Windows.** Встанови [VB-Cable](https://vb-audio.com/Cable/) (безкоштовний) і
перезавантаж комп'ютер. У Zoom → *Налаштування → Аудіо → Динамік* обери **CABLE Input**. У вікні
autopara: «Налаштування» → «Помічник» → «Більше налаштувань» → «Zoom-клієнт» → пристрій **CABLE Output**. Щоб при цьому чути пару й самому:
Win+R → `mmsys.cpl` → *Запис* → *CABLE Output* → *Властивості* → *Прослуховування* → ☑ *Прослуховувати
цей пристрій* → твої навушники чи динаміки. Решта звуку Windows іде як завжди і вухам не потрапляє.

**Zoom-клієнт на macOS.** Встанови [BlackHole 2ch](https://existential.audio/blackhole/). В *Audio MIDI
Setup* → «+» → *Create Multi-Output Device* з BlackHole і твоїми динаміками. У Zoom → *Динамік* обери
цей Multi-Output, а в autopara — пристрій **BlackHole 2ch**.

Не хочеш нічого встановлювати — заходь у Zoom через браузер («Налаштування» → «Акаунти» → «Більше налаштувань» → «Zoom у браузері»); тоді
вуха чують його так само, як Meet. Поки пара в Zoom-клієнті, писати в його чат помічник не вміє:
замість «+» чи «Так, я тут» він надішле тобі, що написати. Вирізки з Zoom-клієнта — голосові (без кадрів).

**Як розпізнається мова.** Це [Whisper](https://github.com/openai/whisper) — модель розпізнавання
мови від OpenAI, запущена локально через [faster-whisper](https://github.com/SYSTRAN/faster-whisper)
на процесорі ноута, без інтернету. Мова примусово українська, тиша відсікається (Silero VAD), а звук
ріжеться на шматки по паузах між фразами (6–25 с), а не посеред слова: Whisper однаково рахує кожен шматок
як 30 с, тож так і точніше, і дешевше. Щоб помилок було менше і вони нічого не ламали:

- **модель**: `auto` на потужному ноуті — `large-v3`. Для української вона помітно точніша за `large-v3-turbo`
  (у turbo урізаний декодер): на тестовій лекції 21–26 % помилкових слів проти 57 %. Важить ~3 ГБ,
  завантажується при першому запуску й розпізнає ~100 с мови за ~70 с. Якщо комп'ютер утричі повільніший
  за мову, програма сама переходить на `large-v3-turbo`, далі на `small`;
- **друге розпізнавання після пари** (`refine.py`): звук пари пишеться у файл (лише локально, у
  `~/.autopara/audio`), а після пари весь запис розпізнається вдруге — як у сервісах субтитрів: з контекстом
  попереднього тексту, beam 5 і запасними «температурами». Модель та сама, але живі вуха завжди першими,
  тож уточнення йде в перервах і після пар, і звіт приходить пізніше. Звіт і запис пари — з уточненої
  розшифровки; жива лишається в кінці файла для порівняння. Звук видаляється, щойно розшифровано;
- **підказка**: Whisper отримує твоє ім'я, ім'я викладача й назву пари, тож рідше їх перекручує;
- **впевненість**: для кожного шматка Whisper сам оцінює, наскільки він певен. Невпевнене
  позначається `[?]` у звіті й для мозку і ніколи не дозволяє дій;
- **фільтри**: відкидаються типові «галюцинації» Whisper на тиші («Дякую за перегляд!», «Субтитри…»),
  випадки, коли модель просто повторює підказку, і зациклення («Тестування, Тестування, …»).

Порівняти моделі на справжньому звуці (на Linux — те, що зараз грає, наприклад лекція українською
на YouTube; на будь-якій ОС — запис лекції з файла):

```bash
autopara listen-test --models small,large-v3-turbo
autopara listen-test --file лекція.mp3 --seconds 60 --models small,large-v3-turbo
```

Команда покаже, що розпізнала кожна модель, де вона не впевнена (`[?]`) і чи встигає за мовою.
Чи чуєш пару ти, вирішує «Налаштування» → «Загальне» → «Без звуку» (`[join] mute_sound`):

- `mute_sound = false` — пару чуєш і ти. Із системним звуком Linux він дублюється в динаміки чи
  навушники (і сам перемикається, коли їх підключаєш); у налаштуваннях звуку GNOME цей дубль
  видно як окремий потік;
- `mute_sound = true` — у динаміках тиша, чують лише вуха.

Мова розпізнається локально й нікуди не надсилається. Розшифровка пари зберігається лише в
`~/.autopara/transcripts` для звіту.

### Мозок

Встанови [Ollama](https://ollama.com/download) — на Arch: `sudo pacman -S ollama && sudo systemctl
enable --now ollama`. Більше нічого: мозок увімкнений за замовчуванням («Налаштування» → «Помічник» → «Мозок»),
програма сама помітить Ollama (навіть якщо її встановили, поки програма працювала), сама завантажить
модель `gemma3:4b` (~3,3 ГБ, поступ видно в «Журналі») і підключить мозок. До того працюють рефлекси. Модель займає ~3,5 ГБ пам'яті, а на i5 11-го покоління
одне рішення займає 10–30 секунд. Тому її кличуть лише тоді, коли вуха чи очі щось помітили,
а термінові речі (тебе назвали, група пише «+») обробляють миттєві рефлекси.
Якщо в репозиторії Arch є збірка Ollama з Vulkan, на Iris Xe вона працюватиме швидше.
Можна взяти іншу модель (`model = "qwen3:4b"` тощо). Головне, щоб вона добре розуміла українську.

### Перевірка

```bash
autopara check                                     # що налаштовано, а що ні
autopara join https://meet.google.com/xxx-xxxx-xxx  # тестова зустріч (створи на meet.new)
```

`join` працює так само, як на справжній парі: показує, скільки учасників бачить, а з `-v` —
що чують вуха. Напиши боту з телефона `напиши тест`, і повідомлення з'явиться в чаті зустрічі.

## Обмеження

- Інтерфейс Meet і Zoom змінюється. Якщо програма не змогла переконатися, що мікрофон
  вимкнений, вона все одно зайде, але з заблокованими мікрофоном і камерою, і напише про це
  в лог. Щоб на такій парі говорити, закрий вкладку й зайди вручну.
- Поки ввімкнено «Без звуку», у динаміках тиша. Якщо змінити це під час пари, нове
  налаштування застосується, щойно вона скінчиться.
- На питання викладача помічник замість тебе не відповідає — лише кличе тебе й показує момент.
- Чат Meet програма читає за розміткою сторінки, перевіреною лише на імітації. Якщо після
  `autopara join` боту не вдається написати в чат, скинь лог, і розмітку поправимо.
- Звук зі сторінки пари перевірений на імітації Meet (WebRTC через `<audio>`) і на програвачах
  Web Audio (так грає Zoom у браузері), а перенесення потоків Zoom-клієнта — на імітації `pactl`.
  Коли звук пари доходить до вух, у «Журналі» з'являється «👂 Чую пару» (для Zoom-клієнта —
  «👂 Слухаю Zoom-клієнт»). Якщо на парі цього рядка немає, скинь лог; на Linux можна тимчасово
  перемкнути «Пари в браузері: звідки брати звук» на весь звук браузера програми.
- У Zoom (і в клієнті, і в браузері) помічник не пише в чат сам — лише підказує тобі, що написати.
- Розумний вихід бачить учасників лише в браузері. З Zoom-клієнтом (`zoom_mode = "app"`)
  програма його не контролює: зазвичай викладач завершує конференцію для всіх, і Zoom
  закривається сам. Якщо хочеш розумний вихід і в Zoom — «Налаштування» → «Акаунти» → «Більше налаштувань» → Zoom у браузері.
- Сайт розкладу ДУІКТ не має офіційного API. Якщо його переробять, програма покаже
  помилку на сторінці «Сьогодні», і треба буде оновити `autopara/rozklad.py`. Для КПІ — `autopara/kpi.py`.
- Посилання в самому розкладі викладачі заповнюють не завжди, тому краще вписати свої
  у «Налаштування» → «Пари».

## Для розробки

```bash
pip install -e ".[dev]"
pytest
```

Тести перевіряють розбір розкладів ДУІКТ і КПІ (на імітації їхніх відповідей), планування пар,
фоновий цикл, вікно програми (Qt без екрана: майстер, автозбереження, Telegram), а також логіку входу в Meet і
Zoom у справжньому Chromium на тестових сторінках, що імітують розмітку Meet/Zoom.

| Файл | Що робить |
| --- | --- |
| `autopara/rozklad.py` | розклад ДУІКТ: форма, CSRF, розбір `var events` |
| `autopara/kpi.py` | розклад КПІ: API schedule.kpi.ua, двотижневий цикл |
| `autopara/sources.py` | вибір джерела розкладу й пошук групи / студента |
| `autopara/config.py` | налаштування: де лежать, перевірка, збереження |
| `autopara/links.py` | правила посилань, посилання Meet/Zoom |
| `autopara/planner.py` | розклад → список «візитів» (коли зайти і вийти) |
| `autopara/joiner.py` | вхід у Meet/Zoom з вимкненими мікрофоном і камерою, підрахунок учасників |
| `autopara/leaving.py` | коли виходити: разом з групою, а не за розкладом |
| `autopara/assistant.py` | помічник: рефлекси, правила безпеки, команди з Telegram |
| `autopara/brain.py` | мозок: локальна мовна модель через Ollama |
| `autopara/ears.py` | вуха: звук вкладки пари, Zoom-клієнта (PipeWire/PulseAudio чи віртуальний кабель) + розпізнавання мови |
| `autopara/ears_tap.js` | збирач звуку учасників у вкладці пари (WebRTC, `<audio>`, Web Audio) |
| `autopara/telegram.py` | Telegram-бот, підключення за кодом і сповіщення на робочий стіл |
| `autopara/media.py` | відеовирізки моментів: кадри сторінки + звук → ffmpeg |
| `autopara/report.py` | звіт після пари й файл з розшифровкою |
| `autopara/wiring.py` | збирає помічника відповідно до конфіга |
| `autopara/power.py` | не дає комп'ютеру заснути, поки сьогодні є пари (Linux, Windows, macOS) |
| `autopara/autostart.py` | запуск разом із комп'ютером (реєстр Windows, XDG autostart, LaunchAgent) |
| `autopara/runner.py` | фоновий цикл |
| `autopara/app.py` | фонова частина: контролер у своєму потоці, `api_*` для вікна, локальний API для інших копій |
| `autopara/gui/` | вікно програми (Qt): головне вікно, майстер, налаштування, автозбереження |
| `autopara/browser_setup.py` | вбудований браузер програми: чи є, завантажити, якщо немає |
| `autopara/checks.py` | перевірка налаштувань (`check` і кнопка у вікні) |
| `autopara/cli.py` | команди `app`, `run`, `import-config`, `schedule`, `login`, `join`, `check` тощо |
